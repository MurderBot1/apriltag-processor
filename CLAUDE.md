# Project rules

Standing rules from the project owner. Every agent (manager and workers) must follow them.

## Workflow: manager and worker agents

- The **manager** (the session in `D:\apriltag-proccessor`) receives tasks and hands them to worker agents. The manager does not do the task work itself. It reviews and merges.
- Each **worker agent** clones `main` into its own folder, `D:/claude/<agent_id>/apriltag-proccessor`, and works only there. Never work in `D:\apriltag-proccessor`.
- Workers do their work on a branch, push it to GitHub, and open a PR to `main`. Workers never merge.
- The manager reviews each PR (CI checks green, diff scoped to the task) and merges it into `main`.
- After every merge the manager pulls the latest `main` into `D:\apriltag-proccessor`.
- If a plain `git push` hangs on a credential prompt, use `git -c credential.helper='!gh auth git-credential' push ...`.
- Side or random tasks given mid-work go to a subagent so the main task keeps going.
- Never fabricate results, prices, links or measurements. Regenerate numbers by running the tools, and report what could not be run or verified.
- Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. PR descriptions end with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.

## Bill of materials

- Whenever you modify the site (`site/`) or anything that changes the parts list (PCB `pcb/`, housing `housing/`, sensor, lens, fasteners, connectors, order or assembly choices), you must also update the BOM in the same PR:
  - edit `docs/bom/bom.json` (value, MPN, quantity, designators, link, unit price, stock, status),
  - regenerate the page with `python docs/bom/build_bom.py`,
  - keep it consistent with `pcb/output/bom.csv`.
- Only mark an item `verified` with an exact MPN, a link and an explicitly stated price. Keep everything else `unverified` with a note. Update `price_checked` when prices are re-checked.

## Dataset and tests

- The test dataset is 100 images in 10 categories (10 each), generated by `tools/make_dataset_100.py` with fixed seeds. Categories are different conditions such as lighting.
- Each category has its own GitHub workflow (`.github/workflows/dataset-<category>.yml`) that tests it and reports the number of successful frames (N/10) back onto the PR.
- A separate workflow (`tests.yml`) runs all of the project's tests on pull requests and on pushes to `main`, and reports pass/fail counts on the PR. Anything excluded from CI must be stated.

## Releases

- Pushes to the `deploy` branch build everything (`tools/build_all.sh`) and create a **new** GitHub Release with the build results attached. Releases are never overwritten.
- `main` holds the latest code and does not create releases. To release, push or merge `main` into `deploy` (`git push origin main:deploy`).
