## The test dataset: 100 images, 10 categories x 10

`test_images/sensor/<category>_<000..009>.png` (1280x800, 8 bit, as the OV9281 would deliver it) with ground truth in
`test_images/ground_truth.json` (per tag: projected corners, visibility, size, incidence angle, occlusion, detectability).
It is generated by `tools/make_dataset_100.py` (Blender Cycles + lens distortion + the sensor model of `tools/make_dataset.py`);
the committed frames are the reference, tests never need Blender. Generation is deterministic: fixed seeds
(`CASE_SEED`, `SENSOR_SEED`), one numpy generator per category, per-frame stratified parameters (a linspace over the 10 frames,
so each category sweeps its condition from mild to severe), rejection sampling so that every frame has at least one detectable tag.
The case list (poses, lights, occluders, sensor knobs) is stored in `test_images/cases.json`.

| category | condition (parameter sweep over its 10 frames) |
|---|---|
| `normal` | clean baseline: nominal light, plain walls, distance 0.8 ... 3.8 m (log spaced) |
| `bright` | over-exposed: light x2 ... x5.5 |
| `dark` | under-exposed: light x0.25 ... x0.03 |
| `lowcon` | low contrast: sensor-side contrast compressed to 42 % ... 24 % around mid-grey |
| `grad` | uneven illumination: strong left/right light gradient, alternating sign, |shift| 2.5 ... 5.5 |
| `shadow` | harsh cast shadow: one spot light, an occluder shadows 10-90 % of a tag |
| `noise` | high sensor noise: sigma x2 ... x4.5 of the nominal model |
| `clutter` | busy background (checker / stripes / brick / busy textures) + 3-22 occluding boxes and spheres |
| `blur` | defocus / motion blur: extra Gaussian sigma 1 ... 3 px, tags 0.9-2.2 m away |
| `persp` | perspective: tag plane tilted 15 ... 74 deg, alternating yaw / pitch and sign, 1.2-3.0 m |

### Reference detector per category (`tools/reference_pipeline.py`, `results/reference_baseline.md`)

A frame *succeeds* when every ground-truth-detectable tag is found and no false id is reported. Measured (python 3.12,
pupil-apriltags 1.0.4): `normal` 10/10, `bright` 10/10, `dark` 10/10, `lowcon` 10/10, `grad` 10/10, `clutter` 10/10, `noise` 10/10,
`blur` 9/10, `shadow` 7/10, `persp` 7/10. 630 of 647 detectable tags found (97.4 %), no false ids, median corner error 0.28 px,
median camera position error 0.7 mm (p95 4.5 mm, max 6.3 mm).

### Whole-pipeline accuracy (RTL simulation of the chip -> firmware solver -> ground truth)

Chip (CSI-2 at 120 fps timing, simulated RTL as it is in this branch) -> tag estimates over SPI -> C pose solver, versus the reference
detector on the *same* 100 images (`tests/run_chain_dataset.py`, `tests/analyze_chain.py`, `results/rtl_chain_results.json`;
measured 474 s for the 100 frames with 12 workers):

| category | detectable tags | chip detects | pose t median / max (mm) | reference t median (mm) |
|---|---|---|---|---|
| normal | 62 | 62 (100 %) | 2.0 / 7.2 | 0.6 |
| bright | 81 | 80 (99 %) | 1.1 / 5.7 | 1.5 |
| dark | 69 | 69 (100 %) | 1.9 / 2.9 | 0.6 |
| lowcon | 66 | **0 (0 %)** | no pose | 1.0 |
| grad | 75 | 75 (100 %) | 1.3 / 2.0 | 0.5 |
| shadow | 47 | 43 (91 %) | 3.0 / 13.6 | 1.9 |
| noise | 57 | 57 (100 %) | 2.2 / 8.0 | 0.7 |
| clutter | 59 | 57 (97 %) | 1.7 / 17.0 | 0.6 |
| blur | 59 | 54 (92 %) | 2.0 / 14.9 | 0.8 |
| persp | 72 | 65 (90 %) | 1.3 / 2.5 | 0.6 |
| **all** | 647 | **562 (86.9 %)** | | reference 630 (97 %) |

0 false-id detections, no dropped frames (single-frame runs). These numbers are with the noise-robust labeller (`rtl/run_ccl.v`: 256 runs
per row, ~3 clocks per run on the common path, label recycling, the 64 largest candidates by area; CCL flags are diagnostics of a degraded
frame, never a rejection). Before that rework the same harness gave **450 / 647 (70 %)**: dark 72 %, noise 70 %, shadow 68 %, clutter 14 %.
The remaining clear weakness is **low-contrast frames (0 %)**, probably the fixed 24-level tile-threshold margin; not investigated.
The chip now misses only a few tags in `blur`, `persp` and `shadow` (small / grazing / shadowed tags).
CCL status flag set on 6 of the 100 frames (candidate table full, i.e. more than 64 candidates, only the 64 largest kept), no dropped rows.

TPU time (`tests/analyze_tpu_budget.py`, `results/tpu_budget_by_category.md`): median 427k clocks, worst 2.55 M (noise). One frame period is
713,840 clocks at 85.714 MHz, so 20 of the 100 frames (clutter 7, noise 6, dark 3, grad 2, shadow 2) would make the *next* frame be dropped
if the whole stream looked like them. Clean frames keep 120.08 fps with no drops (`test_chain.py`).

CCL-only checks (`tests/sweep_ccl_rtl.py`): the RTL candidate table equals the streaming model `golden.stream_components()` (same order); on a
historical 500-frame set (no longer in the repository) at the real 686-clock line 493 of 500 frames were identical, 7 lost 1-5 rows, peak
live labels 167 (258 with dropped rows), slowest row 590 clocks for the busiest frame (113,759 runs). On that historical set the chain
found 2651 of 2825 tags (93.8 %) with 0 false positives, up from 2158 (76.4 %).

## Continuous integration (GitHub Actions)

| workflow | trigger | what it runs |
|---|---|---|
| `dataset-<category>.yml` (10 files: normal, bright, dark, lowcon, grad, shadow, noise, clutter, blur, persp) | pull requests | `tests/ci_category.py <category>` through the reusable `dataset-category.yml`: the 10 frames of that category through the **reference detector** (undistort + pupil-apriltags). Reports `category X: N/10 detected` in the job summary and as one create-or-update PR comment per category (`tools/ci_report.py`, `pull-requests: write`; PRs from forks have a read-only token, so the comment is skipped with a notice and the summary still has the result). Each category is its own check. |
| `tests.yml` | pull requests, pushes to main | `tools/ci_all_tests.py`: `tests/run_all.py --quick` (every pytest group incl. the RTL testbenches via Icarus Verilog and `tb_clock`), `tests/test_i2c.py`, the long RTL simulations `tests/test_csi2.py` + `tests/test_chain.py`, `api/python` tests, `make -C api/cpp test`, `api/java/build.sh`, `cargo test` (api/rust) and a check that `api/testdata/golden_frames.json` is reproducible. Pass/fail counts per suite in the job summary and one PR comment. |

The dataset workflows use the model-level (PC reference pipeline) detector because the RTL chain costs about 40 s per frame
(`tests/run_chain_dataset.py`, 572 s on a 24-thread desktop for the 100 frames) - too slow and too variable for per-PR checks. The
category counts therefore describe the dataset and the reference detector, not the chip; run `tests/run_chain_dataset.py` +
`tests/analyze_chain.py` locally for the chip numbers above. **Not run in CI** (also stated in the workflow report):
`tests/run_chain_dataset.py`, the Blender generation, and the FPGA / PCB / MCU toolchain flows (yosys, nextpnr, KiCad, Pico SDK).
`tests/rtlutil.py` and `tests/atcore.py` use `iverilog`/`gcc` from `PATH` on Linux (the Windows dev box keeps using MSYS2 and the committed .dll files).

## Timing and resources (measured)

120 fps: FS-to-FS period 832,800 clocks @ 100 MHz = **8.328 ms = 120.08 fps**, no dropped frames in multi-frame runs.
Per frame (100-frame set, 100 MHz chain run): the CCL status flags are diagnostics only (6 frames set one, none dropped a row); TPU
427k clocks median, 2.55 M worst (see the table above for how many frames exceed one 713,840-clock frame period). Historical 500-frame
set at the real 686-clock line: slowest CCL row <= 686 clocks in 485 of 500 frames, `done` 185 clocks (median) to 2738 (worst) after the last row.

FPGA (yosys + nextpnr-ecp5, LFE5U-85F-8BG381C): see `docs/fpga.md`.
